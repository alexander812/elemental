# Lexi — описание проекта

Мобильное веб-приложение для заучивания слов по флеш-карточкам. Монорепозиторий с собственной дизайн-системой (иконки + ui-kit). Язык интерфейса — русский.

## Репозиторий

```
app/                      # @elemental/app — само приложение
design-system/icons/      # @elemental/icons — SVG-иконки (React)
design-system/ui-kit/     # @elemental/ui-kit — компоненты, токены, темы, Storybook
skills/new-project/       # скил opencode для скаффолдинга проектов
skills/new-course/        # скил opencode: новый готовый курс и новый язык (JSON по языкам, каталог, валидатор)
skills/new-theme/         # скил opencode: новая цветовая тема (токены, типы, настройки, boot, валидатор)
skills/new-video/         # скил opencode: обучающее видео для «Базы знаний» (движок скринкастов, сценарии, бэклог)
skills/new-onboarding/    # скил opencode: онбординги «первый запуск» и «первое задание» (UI + state, печать текста, подсказки-shake, валидатор)
skills/new-language/      # скил opencode: язык интерфейса — добавить/убрать локаль, переводы сообщений (i18n-скрипт, fallback на английский)

```

Монорепо: npm workspaces (`["app", "design-system/*"]`) + lerna. Корневые скрипты (lerna run): `dev`, `build`, `lint`, `typecheck`, `generate-tokens`, `storybook`.

- `app`: React 19, Vite 8 (rolldown), TypeScript, Effector 23 + effector-react, CSS Modules + PostCSS (pcss), `@fontsource-variable/inter`.
- `ui-kit`: Vite 7 + Storybook 9 (`@storybook/react-vite`), `postcss-nested`, `classnames`.
- Пакеты отдаются исходниками (`main/types: ./src/index.ts`), без шага сборки.
- Платформенные бинарники (esbuild, rollup, rolldown, lightningcss) ставятся только через optional-зависимости самих пакетов из полного lockfile; `overrides` в корне нет.

## Версионирование данных

- Миграции не делаем. При любом изменении моделей данных (`lib/types.ts` и форматы в `transport/*`) нужно поднять `DATA_VERSION` в `app/src/lib/storage.ts` — старые данные из localStorage при этом не преобразуются, а удаляются.
- Каждое значение в localStorage хранится в конверте `{ version, data }` (ключи по-прежнему `app.<key>`). `save` пишет конверт, `load` при обращении к ключу сверяет `version` с текущим `DATA_VERSION`: при несовпадении (или отсутствии/повреждении конверта) ключ удаляется и возвращается fallback (пустые массивы, настройки по умолчанию). То же касается `app.session`.
- Inline-скрипт темы в `app/index.html` читает `app.settings` из конверта (литерал `DATA_VERSION` синхронизирован с `lib/storage.ts`).
- Импорт бэкапов поддерживает только текущий формат (`BACKUP_VERSION` в `transport/backup.ts`), старые форматы не читаются — «Не удалось прочитать файл».

## Деплой (Vercel)

- Настройки проекта: Root Directory — корень репозитория; сборка описана в корневом `vercel.json` (`installCommand: npm ci`, `buildCommand: npm run build --workspace @elemental/app`, `outputDirectory: app/dist`, `framework: null`). Node 22.
- Критично: `package-lock.json` обязан содержать платформенные optional-пакеты (`node_modules/rolldown`, `node_modules/lightningcss-*`, `@rolldown/binding-*`, `@rollup/rollup-*`, `@esbuild/*`). Если их нет, чистая установка на Linux оставляет Vite 8 без `rolldown` и сборка падает (`ERR_MODULE_NOT_FOUND: Cannot find package 'rolldown'`).
- Нельзя добавлять платформенные пакеты прямыми зависимостями и нельзя использовать `overrides` (например, для esbuild): на чужой платформе npm падает с `EBADPLATFORM` на платформенных optional-пакетах. Платформы обеспечивает только полный lockfile.
- Проверка целостности lock: `grep -c '"node_modules/rolldown"' package-lock.json` и `grep -c 'lightningcss-linux-x64-gnu' package-lock.json` (должны быть > 0).
- Пересоздавать lock только в чистой копии репозитория без `node_modules` (`npm install`), после чего проверять сценарий Vercel: свежая копия → `npm ci` → `npm run build --workspace @elemental/app` → `app/dist/index.html`.

## Деплой (GitHub Pages)

- Workflow `.github/workflows/deploy.yml`: push в `main` (или ручной запуск) → `npm ci` → сборка `@elemental/app` с `DEPLOY_BASE=/elemental/` → публикация `app/dist` на GitHub Pages: `https://alexander812.github.io/elemental/`.

В `icon.svg`/`favicon.svg` эмблема отмасштабирована на всю ширину (group transform, границы мозга посчитаны по кривым Безье). PNG-набор сгенерирован из `icon.svg` (maskable — уменьшена под safe zone). `index.html` подключает manifest, apple-touch-icon и meta для standalone на iOS.
- `app/public/sw.js`: предкэш оболочки (`./`, `offline.html`, manifest, favicon, иконки, `sounds/test-success.mp3`) в `elemental-v3`; навигация — network-first: сеть → кэш оболочки → офлайн-заглушка `offline.html` (эмблема, «Something went wrong», кнопка «Restart» — перезагрузка страницы), поэтому без сети и без кэша оболочки вместо ошибки браузера показывается брендированная страница; статика — cache-first с фоновым обновлением; запросы на чужие origin (перевод) не кэшируются. Видеоинструкции (`videos/`) кэшируются так же — после первого просмотра доступны офлайн. Регистрация — в `main.tsx` только в PROD, путь от `import.meta.env.BASE_URL`.

## Модель данных

```ts
Card      { id, texts: { [lang]: string }, learned, deleted, voiceCheck: boolean | null, writeCheck: boolean | null }
CardSet   { id, lessonId, name, active, order, swapped, examPassed: boolean, texts: { [lang]: string }, cards: Card[] }
Lesson    { id, courseId, name, order }
Course    { id, name, description, order, lang, userLang, level?: CourseLevel }
Settings  { theme: 'dark' | 'light' | 'terracotta' | 'midnight' | 'stone' | 'amethyst', userLang, learnAfterChecks: boolean, voiceCheckEnabled: boolean, writeCheckEnabled: boolean, debugMode: boolean, progressionEnabled: boolean }
```

- Иерархия: курс → уроки → задания → карточки. Задания принадлежат уроку (`CardSet.lessonId`), уроки — курсу (`Lesson.courseId`). Курсы создаются/редактируются на экранах `features/courses`, уроки — на экране уроков (`features/lessons`); удаление урока — свайпом вправо с подтверждением, каскадом удаляет все свои задания (`transport/lessons.deleteLesson` + `transport/sets.deleteSetsByLesson`). Курсы не удаляются (один курс всегда выбран).
- `Course.level` (`CourseLevel`: `beginner`, `elementary`, `intermediate`, `upper-intermediate`) — уровень готового курса из каталога (`features/course-search`); у созданных вручную курсов поля нет. По паре «уровень + название + язык курса» определяется дубликат при загрузке готового курса: курс с тем же названием на другом языке дубликатом не считается, поэтому повторная загрузка того же курса под другим языком пользователя добавляет отдельный курс со своей парой языков.
- Ключи localStorage: `app.courses`, `app.lessons`, `app.sets`, `app.settings`, `app.session` (значения — в конверте `{ version, data }`, см. «Версионирование данных»), `app.onboarding` (онбординг и подсказки первого запуска), `app.task-onboarding` (онбординг первого открытия задания), `app.progression` (прогресс мотивации; сохраняется из `features/progression/store`, в бэкап не входит).
- Пара языков закреплена за курсом: `Course.userLang` — язык пользователя на момент создания курса или загрузки готового, `Course.lang` — язык курса. `Settings.userLang` — язык интерфейса и язык для новых курсов/загрузки готовых; смена настройки не меняет уже созданные курсы (чтобы изучать другую пару, курс нужно загрузить/создать заново). `Card.texts` хранит тексты карточки по языкам, `{ ru: 'Понедельник', en: 'Monday' }`; лицевая сторона карточки по умолчанию показывает текст языка курса, обратная — языка пользователя курса, у задания `CardSet.swapped` меняет стороны местами (звук следует за стороной, проверки — нет). Помощник — `lib/cards.ts: getCardText(card, lang)` (с фолбэком на любой доступный язык); `remapTexts(texts, userLang, courseLang)` берёт тексты под парой курса (используется при переносе задания в другой курс). В UI пару урока отдают сторы `$courseLangByLesson` и `$userLangByLesson` (`features/sets/store`).
- `CardSet.texts` хранит текст задания по языкам (`{ ru: '...', en: '...' }`) — исходный текст с экрана «Текст задания» (`features/set-text`) и редактора `features/text-add`. Текст сохраняется по «Сохранить»: для существующего задания — `updateSetTextFx` → `transport/sets.updateSetText(setId, lang, text)`, для черновика в `set-create` — `draftTextSaved` → `$draftTexts` и создание/обновление задания (`createSet`/`updateSet` с `texts`); на экране «Текст задания» по нему строятся сегменты и создаются карточки, там же пустую сторону можно перевести целиком (`translateSetTextFx`: `translateText` + `updateSetTextFx`/`draftTextSaved`). При переносе задания в другой курс тексты ремапятся (`remapTexts`).
- `learned` — карточка выучена (свайп влево), `deleted` — мягко удалена (свайп вверх или «Удалить все карточки»), такие карточки не показываются в колоде и счётчиках, но восстанавливаются.
- `voiceCheck`/`writeCheck` — результат проверки произношения и ввода на карточке (обе проверяют язык курса, кнопки — только на лицевой стороне): `null` (не проверялась), `true` (успех), `false` (ошибка); у новых карточек `null`. `updateCardChecks(setId, cardId, checks)` точечно обновляет значения; импорт бэкапа принимает только текущий формат.
- `Settings.learnAfterChecks` (по умолчанию `false`) — экран «Проверки»; при включении карточка через 2 секунды после успешной проверки автоматически уезжает в выученные (учитываются только включённые способы проверки). `Settings.userLang` (по умолчанию `ru`) — язык пользователя, меняется на экране «Язык».
- `Settings.voiceCheckEnabled` (по умолчанию `true`) — проверка произношения по микрофону; при выключении кнопка микрофона скрыта на карточках, а в режиме теста микрофон не показывается (вместо кнопки play — надпись «Распознавание речи отключено в настройках»). `Settings.writeCheckEnabled` (по умолчанию `false` — из коробки работает только проверка по микрофону) — проверка ручным вводом; при выключении скрыта кнопка клавиатуры и закрывается уже открытая форма ввода (на карточке); в режиме теста клавиатуры нет всегда (тест проверяет только произношение).
- Seed: дефолтный курс не засеивается — `readCourses`/`readLessons`/`readSets` при отсутствии ключа возвращают пустые массивы. Пустое состояние показывается заглушками: на экране курсов — «Пока нет ни одного курса» с кнопкой «Добавить курс», на вкладке уроков без курсов — та же заглушка с кнопкой создания курса. Миграций старых форматов нет — несовпавшая версия данных удаляется (см. «Версионирование данных»).
- `deleteSetsByLesson(lessonId)` — удаление всех заданий урока (каскад при удалении урока).
- `restoreCards(setId, cardIds)` — `deleted=false, learned=false` (возврат в невыученные).
- `resetSet(setId)` — сброс задания к первоначальному состоянию: всем карточкам `learned=false, deleted=false, voiceCheck=null, writeCheck=null`, заданию `examPassed=false` (тексты и id сохраняются).
- `examPassed` (в UI — «тест пройден») — по завершении теста ставится `true`, если все ответы верны, иначе `false`; сбрасывается вместе с `resetSet`. При первом же ответе запущенного теста (верном или неверном) состояние «пройдено» снимается (`setSetExamPassedFx({ examPassed: false })`), поэтому уход из теста без ответов сохраняет прежнюю галочку, а любой ответ — нет. По нему в списке заданий и в списке уроков (если все активные задания урока пройдены) показывается зелёная галочка размером с высоту текста рядом (`IconCheck` 24).
- `updateCard(setId, cardId, texts)` — перезаписывает `texts` карточки под языками пользователя/курса.
- `updateSetText(setId, lang, text)` — сохраняет текст задания под языком (`CardSet.texts`).
- `Progression` (`features/progression`) — XP (`xpLocked` — несгораемые, `xpBurning` — сгораемые, вехи по 500), `coins`, уровни от несгораемых XP (Гуру — 3000 XP + завершённый курс), квесты (`quests`: daily/weekly/сюжет/discovery), `rewarded` (id награждённых — идемпотентность), `counters`/`flags` (метрики квестов), `activeDays`, `frozenDays`, `pinDay`, `burn` (запись о сгорании для восстановления), `certificates`. Начисление: изученное слово +5, успешная проверка +2, тест +25 (+10 без ошибок), урок +50, курс +300, авторское +10 (до 3/день); квесты дают монеты + XP. Сгорание: 2 полных дня без XP (проверка при загрузке/возврате/событии), заморозка +1 день (50 монет, до 3), закрепление (max(30, XP/10), кулдаун 2 дня), восстановление в течение 24 ч (max(50, XP/5)).

## Языки

- Каталог языков — `LANGUAGES_CATALOG` в `lib/languages.ts` (4 записи: `ru Русский`, `en English`, `es Español`, `fr Français`); `LanguageCode = string`, `getLanguageName(code, languages)` с фолбэком на код.
- Все языки каталога доступны сразу — отдельного добавления/удаления языков нет, `$languages` в `features/languages/store` — константный стор с каталогом.
- Дефолты: язык пользователя — русский (`DEFAULT_USER_LANG`), язык курса — английский (`DEFAULT_COURSE_LANG`).
- Язык пользователя задаётся в настройках: меню «Настройки» → «Язык» (`features/settings/ui/LanguageView.tsx`, экран `language`) — список всех языков каталога (Radio), выбор сохраняется в `Settings.userLang` (`setUserLangFx` → `transport/settings.saveUserLang`). Этот же выбор — язык интерфейса (переведены ru/en/es/fr, для кодов без файла локали показывается английский, см. «Локализация интерфейса») и язык для новых курсов и загрузки готовых; у уже созданных курсов своя пара (`Course.userLang`/`Course.lang`).
- Язык курса задаётся на экране создания/редактирования курса (`features/courses/ui/CourseCreateView.tsx`) одним `Select` («Язык курса»); язык пользователя в списке недоступен, одинаковые языки запрещены. При создании за курсом закрепляется пара «текущий `Settings.userLang` + выбранный язык курса»; при редактировании пара не меняется (название и описание правятся на языке пользователя курса).
- Уроки наследуют пару языков из курса и не меняют её: на экране урока (`features/lessons/ui/LessonCreateView.tsx`) можно выбрать курс (перенести урок) — пара берётся у нового курса; имя урока пишется и озвучивается на языке пользователя курса. У задания своей пары языков нет. Перенос задания в урок другого курса меняет пару: тексты пар и тексты задания переносятся по языковым ключам (`remapTexts`), поэтому текст нового языка (если его не было) даёт пустое поле.
- Создание карточки (`CardCreateView`) пишет тексты под парой курса; перевод (`transport/translate.ts`, ISO-код) и озвучка (`transport/speech.ts`, локаль по коду) работают для языков каталога. `speak()` выбирает способ сам: при наличии моста — нативный `speak`, иначе Web Speech API (`canSpeak()` учитывает оба варианта).

## Локализация интерфейса

- Все тексты интерфейса — сообщения react-intl: статические в JSX — `<FormattedMessage id defaultMessage>`; строковые пропсы (`Select.label/placeholder`, `aria-label`/`ariaLabel`), собранные строки и сообщения в хуках — `intl.formatMessage`; тексты из `lib/` и сторов возвращаются как `MessageDescriptor` и форматируются в UI (`shared/ui/Toast`).
- `defaultMessage` всегда английский — он же фолбэк. Переводы лежат в `app/src/lib/i18n/messages/<locale>.json` (плоский `{ id: текст }`); файл = подключённая локаль. Нет ключа или файла локали — показывается английский текст без ошибок. `messages/en.json` — снимок английских текстов для контроля изменений (в рантайме не используется: `IntlProvider` пропускает en, английский всегда берётся из `defaultMessage`).
- Язык интерфейса — `Settings.userLang` (настройка «Язык»); `IntlProvider` в `ThemeRoot.tsx` покрывает всё приложение (включая Toast и онбординг), `document.documentElement.lang` синхронизируется с настройкой.
- id — `scope_element_key` (snake_case), scope = фича/экран (`cards_*`, `sets_*`, `settings_*`, `common_*`). Один id = один английский текст; переменные — ICU (`{name}`, `{count, plural, one {} other {}}`), числа не склеиваются конкатенацией.
- Новые компоненты и фичи не переводятся автоматически: по умолчанию добавляется только английский `defaultMessage`. Переводы в ru/es/fr добавляются по явному запросу; где перевода нет — английский.
- Не переводятся: названия языков в каталоге (эндонимы), уровни курсов (Beginner…), имена голосов, бренд Lexi, контент готовых курсов (`app/src/courses/*.json`), названия артефактов из Android-моста.
- Слежение: `npm run i18n` — сводка (локали + статус снимка); `npm run i18n -- --locale es` — список непереведённых id с английскими текстами; `-- --stale` — какие английские тексты изменились/добавились/удалились и какие переводы (ru/es/fr) нужно обновить; `-- --write-en` — принять новый снимок `messages/en.json`; `-- --json` — машиночитаемо; `-- --check` — структурная проверка + дрейф снимка (id без `defaultMessage`, конфликты текстов, лишние ключи, несовпадение ICU-переменных; exit 1 при проблемах).
- Изменение английского текста при том же id: сначала `-- --stale` (видно, какие переводы устарели), обновить их, затем `-- --write-en`; новые id — только `--write-en` без переводов (переводы — по запросу).
- Добавление и удаление языка интерфейса (файл локали, переводы, проверки) — скилл `new-language`.

## Навигация (`features/navigation/store`)

- Состояние `$nav: { stack: Screen[], transition }`; события `pushScreen`, `popScreen`, `replaceScreen` (заменяет верхний экран стека), `popTo`, `goToRoot`, `transitionEnded`; производные `$stack`, `$screen`, `$transition`, `$canGoBack`.
- Экраны: `courses` (корень), `progress` (уровень, XP, монеты, квесты, сертификаты — открывается чипом в шапке курсов), `course-create{courseId?}` (создание/редактирование курса), `course-search` (поиск готовых курсов), `lessons` (уроки текущего курса), `lesson{lessonId}` (задания урока), `lesson-create{lessonId?, courseId?}` (создание/редактирование урока), `set-create{setId?, lessonId?}` (создание; с `setId` — редактирование задания), `cards{setId}` (карточки; там же режим теста), `set-intro{setId}` (приветственный экран задания), `set-text{setId}` / `set-text{draft}` (текст задания), `card-create{setId, cardId?}`, `cards-restore{setId}`, `text-add{setId}` / `text-add{draft}` (редактор текста), `words-translate{setId}`, `settings`, `theme`, `language`, `voices`, `knowledge{videoId?}` (база знаний с видеоинструкциями), `recognition` (настройки распознавания речи), `checks`, `about` («О приложении»), `data`, `export`. Вкладки футера «Курсы» и «Уроки» — корневые страницы: `goToRoot` сбрасывает стек к `courses`, `goToLessons` — к `lessons` (текущий курс — `$currentCourseId`).
- `popTo(name)` срезает стек до последнего экрана с таким именем (например, после добавления карточек из текста — `popTo('cards')`).
- Анимации (`AppLayout.tsx` + `AppLayout.module.pcss`): при push новый экран выезжает слева (`slide-in-left`, класс `screenEntering`); при pop уходящий экран уезжает влево оверлеем (`slide-out-left`, класс `screenExiting`, очистка по `animationend` и таймауту 400мс через `transitionEnded`); оверлей помечен `inert` — его копия экрана не перехватывает фокус (иначе `autoFocus` поля заново открывал клавиатуру). При смене экрана `main` скроллится вверх. Учитывается `prefers-reduced-motion`.
- `lib/ghostClick.ts`: после навигации включается подавление совместимых mouse-событий (mousedown/mouseup/click) без предшествующего `pointerdown` — защита от «призрачного» клика по новому экрану после тач-тапа (иначе, например, вход в задание автоматически переворачивал карточку). Suppressor «взводится» на `pushScreen`/`popScreen`/`replaceScreen`/`goToRoot`.

## Экраны и функционал

- **Онбординг** (`features/onboarding`, UI + state в одной папке): при первом запуске поверх приложения (после готовности данных, `$appReady`) показывается полноэкранный `ui/OnboardingView` — по центру эмблема, заголовок «Добро пожаловать в Лекси» и описание возможностей печатаются посимвольно, после окончания печати снизу плавно проявляются кнопки «Смотреть видео» (открывает общий ролик `overview` в базе знаний: `pushScreen({ name: 'knowledge', videoId: GENERAL_VIDEO_ID })`) и «Открыть базу знаний»; крестик в правом верхнем углу закрывает онбординг. Пока онбординг открыт, он не пропускает взаимодействие с приложением; закрытие/нажатие кнопки пишет `completed` в `app.onboarding`. `store` хранит `{ completed, hints }`; хук `ui/useShakeHint(hint, active)` впервые включает на элементе анимацию shake (класс `shake.module.pcss`, 700мс) и после `animationend` (или таймаутом) помечает подсказку показанной. Подсказки: `courses-add` — кнопка «Добавить курс» на заглушке экрана курсов, `first-lesson` — первая строка списка уроков, `test-button` — кнопка «Тест» после того, как пролистаны все карточки колоды (один раз). Хук `ui/useDelayedShake(active, delayMs, onFinished)` — тот же shake, но с задержкой; используется для карточки добавленного курса. Второй вариант — `variant="task"` (`$taskOnboardingOpened`, ключ `app.task-onboarding`): при первом открытии задания (экраны `set-intro`/`cards` — `isTaskScreen` в `AppLayout`), только после завершения первого онбординга (`!onboardingOpened`), тот же печатающийся экран с заголовком «Как работать с заданием», кнопка «Смотреть видео» открывает ролик о заданиях (`pushScreen({ name: 'knowledge', videoId: TASK_VIDEO_ID })`), крестик/кнопки пишут `completed` в `app.task-onboarding` — второй раз не показывается.
- **Прогресс** (`features/progression`): виджет прогресса (бейдж уровня-картинка, XP и монеты; при поступлении XP звезда «подмигивает», монета переворачивается, числа догоняют с анимацией; при сгорании в запасе ≤1 дня — тревожный цвет) — в шапке «Курсы» справа, на экранах «Уроки», «Задания урока» и на карточках/тесте — по центру вместо названия (при выключенной настройке виджет скрыт, названия возвращаются). Тап по виджету — экран `progress`: карточка уровня (бейдж, имя, полоса до следующего, для Гуру — «завершите курс»), карточка XP (несгораемые/сгораемые, монеты, дедлайн сгорания, кнопки «Заморозить за 50», «Закрепить за max(30, XP/10)», восстановление сгоревшего за max(50, XP/5) в течение 24 ч), квесты (ежедневные 3, недельный, сюжетная цепочка «Первый курс», разовые discovery), сертификаты завершённых курсов и свитч «Прогресс и награды» (`Settings.progressionEnabled`). Награды: слово +5 XP, проверка +2, тест +25 (+10 без ошибок), урок +50, курс +300, авторское +10 (до 3/день); квесты — монеты + XP; веха каждые 500 XP закрепляет сгораемые. Сгорание — 2 полных дня без XP; при загрузке/возврате показывается оверлей `BurnNotice` (восстановить за монеты или закрыть), новый уровень — оверлей `LevelUpNotice` (салют + конфетти). Данные — ключ `app.progression`. При выключенной настройке награды не начисляются и сгорание не срабатывает, при включении — свежее окно.
- **Курсы** (`features/courses/ui/CoursesView.tsx`, экран `courses`): корневой экран. Нужно <текст языка курса>, ваш текст <текст>` (ввод); со звуком (`lib/sounds.ts: playSuccess/playError`, `unlockSounds` по тапу) и вибрацией (`vibrateSuccess`/`vibrateError`); если в настройках включён `learnAfterChecks` и успешны все включённые проверки, через 2 секунды после статуса карточка с анимацией уезжает в выученные; клик не переворачивает карточку и не начинает свайп (stopPropagation на pointerdown/click); фильтры «выучено/не выучено» с количеством; между ними по центру — кнопка с иконкой текста (`IconViewList`, aria-label «Текст задания») с переходом на приветственный экран `set-intro` при наличии текста (иначе — редактор `set-text`; активна всегда); меню «…» (bottom sheet, общий компонент `features/sets/ui/SetMenu` — то же меню и на приветственном экране задания): «Редактировать» (открывает `set-create{setId}`), «Поменять местами» (переключает `CardSet.swapped` — стороны карточки меняются местами вместе со звуком, проверки продолжают проверять язык курса), «Удалить все карточки» (мягко; на карточках — по текущему фильтру, на приветственном экране — все карточки), «Восстановить удалённые», «Сбросить результаты» (bottom sheet `ConfirmSheet` с текстом «Вы уверены, что хотите сбросить результаты? Карточки вернутся в невыученные, как будто вы их не трогали.» и кнопками «Да»/«Отмена»; по «Да» — `resetSetFx` → `transport/sets.resetSet`: всем карточкам `learned=false`, `deleted=false`, `voiceCheck=null`, `writeCheck=null`, заданию `examPassed=false`; локальные фильтры/сессия сбрасываются), «Удалить задание» (безвозвратно: `deleteSetFx` удаляет задание с карточками; на карточках перед этим — инлайн-подтверждение в области колоды, затем `popScreen`; на приветственном экране — `ConfirmSheet`, затем `popTo('lesson')`); пустые состояния и финалы: «Начать сначала» (когда всё просмотрено, но есть невыученные), «Все карточки выучены» + «Перейти к следующему заданию» (следующий задание берётся в рамках урока, иначе возврат на экран урока); в фильтре «выучено» после просмотра всех выученных — «Повторить» (сбрасывает сессию просмотра), а если выученных нет — пустой экран «Нет выученных карточек»; внизу — кнопка «Тест» (показывается всегда, когда в задании есть карточки, независимо от фильтра и `examPassed`); нижней кнопки «Добавить» нет — добавление переехало в меню «…»: пункт «Добавить карточку» открывает `card-create{setId}` (на первом месте в меню). В режиме изучения автоматического режима нет (ни кнопки `play`, ни `stop`). Режим теста (локальный стейт экрана; экзамен как отдельный экран убран): показывается та же колода, но лицевой текст — язык пользователя, флип и свайпы отключены, скрыты все кнопки кроме микрофона (фильтры «выучено/не выучено» с кнопкой текста, подсказки свайпов, меню в шапке — заголовок «Тест», стрелка «назад» выходит из теста), внизу вместо «Тест» — ряд «Отмена» и круглая кнопка `play`/`stop`. Кнопка `play` включает автоматический режим: на каждой карточке через 1 с сам включается микрофон (`recognizeFx` по языку курса, `ensureAsrReadyFx`; при незагруженной модели шит распознавания открывается, автоматический режим выключается), при вердикте `good` играют `playSuccess`/`vibrateSuccess` и карточка уезжает в «выученные»; при неудаче показывается «Ошибка!» с «Осталось попыток: N» (в режиме дебага — ещё и что распознала модель), даётся 3 попытки (микрофон включается снова сам), после третьей карточка уезжает в «не выученные»; кнопка `stop` в это время мигает прозрачностью (CSS-анимация) и выключает режим. Без автоматического режима пользователь сам нажимает микрофон: правильный ответ — карточка сама уезжает в выученные, неправильный — те же 3 попытки (сообщение дополняется «Осталось попыток: N», можно сразу повторить) и уход в невыученные; сообщение о неудаче правильный ответ не подсказывает — просто «Ошибка!» (в изучении сообщение по-прежнему показывает услышанное и нужный текст); молчание и ошибки распознавания попытку не расходуют; после двух неудачных попыток на одиночном слове короче 5 букв автоматический режим выключается и вместо кнопок открывается поле ввода с клавиатуры с той же подсказкой: верный ввод засчитывается как правильный ответ, неверный расходует попытку («Ошибка! Осталось попыток: N»). Сообщение о вердикте показывается в карточке 1 с, затем карточка с анимацией уезжает (260 мс) и показывается следующая. Результаты теста нигде не сохраняются — в тесте не вызываются `setCardLearnedFx`/`updateCardChecksFx`, выученность существует только до конца прогона. Очередь — все неудалённые карточки с текстом языка курса. Когда все пройдены, показываются результаты (`shared/ui/ExamResults`: жёлтый смайлик, строки «Правильных ответов»/«Ошибок», «Пройти тест снова»/«Вернуться к обучению»/«Перейти к следующему заданию»), при полном успехе — `playTestSuccess` (звук `public/sounds/test-success.mp3`) и конфетти, иначе `playDisappointment`; по завершении `setSetExamPassedFx` ставит `examPassed` (все верно — «пройдено»), а результаты прогона переносятся в изучение: карточкам с верными ответами ставится `learned=true`, карточки с тремя ошибками — `learned=false` (`setCardLearnedFx` вызывается только для изменившихся), поэтому после теста колода в изучении сразу отражает итог. Если запустить тест по уже пройденному заданию, при первом же ответе (верном или неверном) `examPassed` снимается — галочка гаснет, пока тест не завершён. «Пройти тест снова» сбрасывает прогон, «Вернуться к обучению» выходит из режима теста, «Перейти к следующему заданию» открывает следующее активное задание урока (`findNextSet`/`nextSetScreen` в `helpers.ts`), а после последнего задания урока — экран со списком заданий (`popTo('lesson')`). Если распознавание выключено в настройках или недоступно на устройстве, микрофон не показывается, кнопки `play` нет, а под колодой — «Распознавание речи отключено в настройках»/«Распознавание речи недоступно на устройстве». Пока идёт тест (включая экран результатов), экран смартфона не гаснет (`setKeepAwake(true)` → `transport/wakeLock.ts`: мост `keepScreenOn` или Screen Wake Lock API). Когда пользователь пролистал все карточки колоды, кнопка «Тест» один раз трясётся (подсказка `test-button` → `useShakeHint`).

- **Данные** (`features/backup`, экраны `data` и `export`): «Экспортировать» открывает экран выбора данных (`ui/ExportView.tsx`) — дерево курсов и вложенных уроков (слева Checkbox) и сверху чекбокс «Выбрать все»; чекбокс курса отмечен, если выбран хотя бы один его урок, выбор курса отмечает все его уроки (отдельные уроки можно снять); кнопка «Экспортировать» скачивает JSON-файл `lexi-backup-ГГГГ-ММ-ДД.json` (`transport/backup.ts: createBackup(lessonIds)` + `downloadBackup`): `{ version: 8, exportedAt, courses, lessons, sets, languages, settings }` (экспортируются выбранные уроки и их курсы; задания в `sets` включают текст `texts`; `languages` — каталог, для совместимости; `settings` — тема, язык пользователя, проверки и режим дебага). «Импортировать» — скрытый `input[type=file]`, `parseBackup` принимает только текущий формат (`version === BACKUP_VERSION` и нужные массивы; старые форматы не читаются — «Не удалось прочитать файл»), показывает превью (имя файла, число курсов/уроков/заданий/карточек) и две кнопки: «Слияние» — `importBackupFx({ backup, mode: 'merge' })` добавляет курсы и уроки из файла к текущим; курс с существующим названием дополняется, а совпадающие по названию уроки того же курса показывает в bottom sheet (`ConfirmSheet`) с «ОК»/«Отмена» и по «ОК» полностью перезаписывает их задания и карточки (ID совпадающих уроков сохраняются, метаданные курса обновляются из файла); данные приложения, которых нет в файле, остаются; «Замена» (`mode: 'replace'`) полностью заменяет `app.courses`/`app.lessons`/`app.sets` и `app.settings`. После импорта `$courses`/`$lessons`/`$sets`/`$settings` обновляются через `.on(importBackupFx.doneData)` и вызывается `goToRoot`; невалидный файл — подсказка «Не удалось прочитать файл». «Сбросить данные» (подпись «Вернуться к начальному состоянию», `resetDataFx` из `features/backup/store`) — `ConfirmSheet` с «Сбросить»/«Отмена»: по подтверждению `lib/storage.clearAll()` удаляет все ключи `app.*`, и приложение перезапускается (`window.location.reload`), возвращаясь к seed. Фича — `features/backup` (store + ui).

## Android-обёртка

- `/Users/a.smirnov/p/lexi-android` — отдельный репозиторий (создан из шаблона `/Users/a.smirnov/p/android-webview-template`): WebView-обёртка Lexi с мостом `vibrate`/`deviceInfo`/`scanText`/`speak`, OCR на Tesseract4Android (вшиты ru/en, остальные языки скачиваются при первом использовании).
- URL веб-приложения настраивается в `app/webview.properties` (debug → `webview.devUrl`, release → `webview.prodUrl` = GitHub Pages).
- Аппаратная кнопка «назад»: `MainActivity` выполняет в WebView `(window.__lexiBack && window.__lexiBack()) === true`; веб-приложение регистрирует `window.__lexiBack = handleAndroidBack` (`main.tsx` → `features/navigation/store`), который при открытом bottom sheet закрывает его (`closeTopBottomSheet`) и возвращает `true`, иначе при стеке больше одного экрана делает `popScreen()` и возвращает `true` (как кнопка «назад»), иначе — переход по истории WebView (`canGoBack`), иначе сворачивание приложения `moveTaskToBack(true)` (обработчик остаётся включённым); `handlingBack` сбрасывается по таймауту, чтобы обработчик не «залипал».
- Кнопка «Сканировать текст» на экране `text-add` работает через `lib/nativeBridge.ts`; в браузере она скрыта.
- Вибрация при свайпах карточек — `transport/haptics.ts` → `callNative('vibrate', { durationMs })` (в Android `NativeBridge` использует `VibrationEffect.createOneShot`, ограничение 1–10000мс); в браузере вызовов нет.
- Удержание экрана включённым на время теста — `transport/wakeLock.ts` → `setKeepAwake(true/false)`: в Android `callNative('keepScreenOn', { enabled })` (`NativeBridge` ставит/снимает `FLAG_KEEP_SCREEN_ON` у окна активити через `runOnUiThread`), иначе — Screen Wake Lock API (`navigator.wakeLock.request('screen')`, лок снимается системой при скрытии страницы и перезапрашивается по `visibilitychange`); старые сборки Android без метода `keepScreenOn` используют тот же веб-фолбэк; в браузерах без API вызовы игнорируются.
- Озвучка карточек — `callNative('speak', { text, lang })`: `speech/SpeechService.kt` выбирает способ — скачанный локальный нейроголос (`speech/LocalTts.kt`) → системный `TextToSpeech` (`speech/SpeechSynthesizer.kt`, очередь до `onInit`, `QUEUE_FLUSH`; в манифесте — `<queries>` с `TTS_SERVICE` для Android 11+) → ошибка `voice_missing`; в браузере и без моста — Web Speech API.
- Распознавание речи — `callNative('recognizeSpeech', { lang })`: `speech/RecognitionService.kt` выбирает способ — системный `SpeechRecognizer` (`ACTION_RECOGNIZE_SPEECH`, локаль по языку, до 3 вариантов и confidence) → on-device (`createOnDeviceSpeechRecognizer`, Android 12+) → офлайн-модель Whisper tiny (sherpa-onnx, int8) через `speech/OfflineAsr.kt` (AudioRecord + VAD + `OfflineRecognizer`, `OfflineWhisperModelConfig(language)` — язык передаётся в декодер, поэтому ответ всегда на ожидаемом языке, языки ru/en/es/fr, архив ~116 МБ, `speech/AsrManager.kt` качает tar.bz2 с GitHub, распаковывает int8 encoder/decoder и tokens; если системный движок вернул ошибку «язык недоступен» или результат в чужой письменности — кириллицу для английского, — распознавание повторяется офлайн-моделью); запрашивает `RECORD_AUDIO` в рантайме, ошибки — `permission_denied`/`no_speech`/`network`/`busy`/`language_not_supported`/`asr_download_failed`; `cancelRecognizeSpeech` останавливает распознавание (системный `cancel()`, офлайн — флаг отмены); синхронный `hasRecognition()` отдаёт доступность (web зовёт через `callNativeSync`); артефакты распознавания (`speech/AsrCatalog.kt`: id, title, description, размер, архив, языки, движок) отдаёт `asrStatus` — список `{ artifacts: [{ id, title, description, sizeBytes, languages, installed, downloading, progress, error }] }`; две модели: английская NeMo Conformer CTC small (`nemo-en-conformer-small`, архив ~76 МБ, лучше держит одиночные английские слова, не галлюцинирует) и мультиязычная Whisper tiny (`whisper-tiny-multilingual`, архив ~116 МБ, ru/en/es/fr); для языка выбирается самая специфичная скачанная модель (для английского — NeMo, мультиязычная — фолбэк), `speech/OfflineAsr.kt` собирает конфиг по движку (`nemo_ctc` или `whisper`) и кеширует распознаватель по паре «модель+язык»; `downloadAsr { id }` скачивает модель с прогрессом (резолвится по завершении), `deleteAsr { id }` удаляет; загрузка идёт в foreground-сервисе `speech/DownloadService.kt` (тип `dataSync`, общий для моделей распознавания и голосов: уведомление с процентами и переходом в приложение — процесс не замораживается и загрузка продолжается при автоблокировке экрана; `AsrManager`/`VoiceManager` — синглтоны, `release()` не трогает активную загрузку, POST_NOTIFICATIONS спрашивается при старте загрузки); веб-приложение по клику микрофона проверяет `fetchAsrArtifacts` и при отсутствии модели открывает шит с прогрессом и экраном «Распознавание речи» (Настройки); в браузере — Web Speech API (`webkitSpeechRecognition`), в Android WebView не работает. В манифесте — `RECORD_AUDIO`, `FOREGROUND_SERVICE`/`FOREGROUND_SERVICE_DATA_SYNC`/`POST_NOTIFICATIONS`, сервис `DownloadService` (`foregroundServiceType="dataSync"`) и `<queries>` с `android.speech.RecognitionService`.
- Офлайн-голоса — sherpa-onnx (Apache-2.0): AAR `app/libs/sherpa-onnx-1.13.8.aar` (нативные либы только arm64-v8a/armeabi-v7a, APK ~96 МБ) + Piper-модели (`speech/VoiceCatalog.kt`), скачиваются по кнопке на экране «Озвучка» (~64–80 МБ): сначала HuggingFace `csukuangfj/vits-piper-<id>` (`.onnx` + `tokens.txt`), при ошибке — GitHub-релиз `tts-models` (tar.bz2 через commons-compress); всё кладётся в `filesDir/tts`, общий `espeak-ng-data` вшит в APK (`assets/tts/espeak-ng-data.zip`), синтез и воспроизведение — через AudioTrack. Управление — мост `ttsVoices`/`downloadVoice`/`deleteVoice` (`speech/VoiceManager.kt`, синглтон `VoiceManager.get`); ошибки загрузки приходят в `error` с деталями; скачивание идёт через общий с распознаванием foreground-сервис `speech/DownloadService.kt` (уведомление «Загрузка голоса: …» с процентами, продолжается при блокировке экрана).
