# Обучающее видео для «Базы знаний»

## Контекст (прочитать перед работой)

- Экран — `app/src/features/knowledge/ui/KnowledgeView` (экран навигации `knowledge`, пункт меню «База знаний»). Превью-карточка: постер, полупрозрачное затемнение, название в верхнем регистре; тап — полноэкранный плеер на `BottomSheet fullHeight` с крестиком.
- Список видео — `app/src/features/knowledge/videos.ts` (`KNOWLEDGE_VIDEOS`: `id`, `title`, варианты `ru`/`en` с `src` mp4 и `poster`).
- Файлы — `app/public/videos/<locale>/<id>.mp4|.jpg` (пути строятся от `import.meta.env.BASE_URL`). Язык интерфейса `ru` получает русские ролики, `en`/`es`/`fr` — английские (fallback `en`).
- Видео грузится **только по клику** (элемент `<video>` монтируется вместе с плеером), постеры — `loading="lazy"`. Список может расти без оглядки на вес видео.
- Движок записи — `skills/new-video/engine/`: `runner.cjs` (Playwright: настоящие тапы, свайпы, ввод, виртуальный курсор, сцены с печатающимся текстом и тултипы у элементов) и `audio.cjs` (сборка mp4 + звук + постер).
- Сценарии — `skills/new-video/scenarios/`: текстовый сценарий `<id>.<locale>.md` (что показываем, что объясняем, каким голосом — по брифу; шаблон `_template.md`) и программа записи `<id>.<locale>.cjs` (шаблон `_template.cjs`). По .cjs ролик пересобирается; .md — первоисточник замысла.
- План роликов — `skills/new-video/SCENARIOS.md`.

### Зависимости движка

`playwright-core` и `ffmpeg-static` ищутся в `node_modules` репозитория, затем в `$TMPDIR/opencode/e2e`. Если их нет:

```bash
mkdir -p "$TMPDIR/opencode/e2e" && cd "$TMPDIR/opencode/e2e" && npm i playwright-core ffmpeg-static
```

Chromium берётся из кеша ms-playwright (`$TUT_CHROMIUM` — чтобы указать явно). `say` (macOS) нужен только для озвучки. Для нейросетевого диктора (голос `edge:<имя>`) — `python3 -m pip install --user edge-tts` (список голосов: `python3 -m edge_tts --list-voices`, для русского — `ru-RU-DmitryNeural`, `ru-RU-SvetlanaNeural`).

### Переменные окружения

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `TUT_OUT` | `$TMPDIR/opencode/tutorial-out` | каталог артефактов (webm, timeline.json, mp4, jpg) |
| `TUT_BASE` | `http://localhost:5173/` | адрес приложения |
| `TUT_CHROMIUM` | свежий из кеша ms-playwright | путь к Chromium |

## Ключи шага

Шаг — один объект; действие одно, остальное — оформление. Полный список — в шапке `engine/runner.cjs`.

| Ключ | Что делает |
| --- | --- |
| `scene` | карточка шага `{ title: 'Шаг 1', text: 'Для начала загрузим курс.' }`: затемнение, заголовок и текст, печатающийся по буквам (45 мс/буква, пауза 1500 мс) |
| `hint` | тултип у элемента действия: `{ hint: 'Выберите уровень владения языком', tap: 'Выберите уровень' }` — подсветка рамкой, пауза (по умолчанию 1400 мс, в обучающих роликах — ~2500 мс), действие, скрытие; работает с `tap`/`swipe`/`type`, без действия — висит по центру сверху; `hintRing: false` — без рамки вокруг элемента |
| `tap` / `tapAt` | тап по кнопке/radio/тексту или по координатам; `touch: true` — тап тач-событием (для переворота карточки) |
| `hold` | длинное нажатие: `{ hold: { target: 'windowsill', ms: 3200 } }` — перевод слова по удержанию (тултип виден, пока держишь) |
| `type` | ввод: `{ target: 'Название курса', text: 'Привет', delay: 90 }` |
| `swipe` | свайп: `{ target: 'Monday', dir: 'left' }` |
| `back` | тап по стрелке «назад» |
| `wait` / `pause` | пауза до/после действия |
| `speech` / `speechError` / `speechDelay` | что «услышит» распознавание при тапе по микрофону |
| `say` / `sayLang` / `sayDelay` / `sayRate` / `voice` | реплика для звуковой дорожки: macOS `say` или нейросетевой голос `voice: 'edge:ru-RU-DmitryNeural'` (edge-tts) |
| `eval` | произвольный код в контексте страницы |

Кроме шагов сценарий может задать `initScripts` (init-скрипты страницы — мок Android-моста,
пример `scenarios/task.ru.cjs`) и `routes` (подмена сетевых запросов — заглушка переводчика).

## Шаги

1. **Сценарий.** Сначала текстовый сценарий `skills/new-video/scenarios/<id>.<locale>.md` по `_template.md` (цель, титры шагов, тултипы, объяснения и голоса), затем программа записи `<id>.<locale>.cjs` по `_template.cjs`. `seed` — состояние стора на старте (курс/урок/задание/карточки/настройки), `steps` — действия. Список ключей шага — в шапке `engine/runner.cjs`.
2. **Запись.** Подними приложение и запусти движок из корня репозитория:

   ```bash
   npm run dev
   node skills/new-video/engine/runner.cjs skills/new-video/scenarios/<id>.<locale>.cjs
   ```

   Результат: `$TUT_OUT/<name>.webm` + `<name>.timeline.json`. Движок печатает шаги и ошибки страницы; при падении пишет, какой элемент не нашёл и что сейчас на экране. Для отладки подсказок: `TUT_DEBUG_HINT=1` печатает координаты тултипа.

3. **Проверь кадры** (playwright-ffmpeg умеет только webm, поэтому смотри через ffmpeg-static):

   ```bash
   FF=$(node -e "console.log(require('$TMPDIR/opencode/e2e/node_modules/ffmpeg-static'))")
   $FF -y -ss 3 -i "$TUT_OUT/<name>.webm" -frames:v 1 /tmp/frame.png
   ```

4. **Сборка и публикация** (mp4 + постер сразу в приложение):

   ```bash
   node skills/new-video/engine/audio.cjs <name> --trim=auto --poster=0.6 --to=app/public/videos/<locale>
   ```

   `--trim=auto` отрезает загрузку приложения до первого кадра (по `timeline.readyMs`), поэтому постер и начало ролика — ровно тот экран, с которого начинается сценарий. Если в сценарии есть реплики `say`, звук подмешивается в mp4 автоматически (`--offset=<мс>` — подстройка, `--voice-ru=` и т.п. — голоса).

5. **Регистрация** — строка в `KNOWLEDGE_VIDEOS` (`app/src/features/knowledge/videos.ts`) через `video(id, title)`: он собирает варианты `ru`/`en` из `asset('videos/<locale>/<id>.<ext>')`. `id` = имя файла, `title` — как показывать на карточке (заглавные буквы делает CSS).

6. **Проверка.** `npm run lint`, `npm run typecheck`, `npm run build`; в приложении — Настройки → База знаний: постер, клик, полноэкранный плеер, крестик. Проверь оба языка интерфейса (ru и en). Быстрый смоук (если есть) — `node $TMPDIR/opencode/e2e/knowledge-check.cjs`. Файлы видео и правки — в git.

## Правила съёмки

- Формат — **портрет 390×844** (запись 780×1688), тёмная тема; так же выглядит и на телефоне.
- Ролик начинается с **реального состояния приложения**: у свежей установки курсов нет (экран «Пока нет ни одного курса»), онбординг пройден — движок сам ставит `app.onboarding`, если в `seed` его нет.

### Озвученные ролики (диктор) — основной формат

- **Тултипы не используем.** Каждое действие объясняет диктор, а этапы разделяют
  карточки-титры `scene` («Шаг N» + фраза о шаге).
- Диктор отвечает на два вопроса: **что делаем** и **зачем**. Пример: «Нажимаем «Загрузить» —
  приложение скачает курс и добавит его в ваши».
- Голос — нейросетевой edge-tts: `voice: 'edge:ru-RU-DmitryNeural'` (список: `python3 -m edge_tts --list-voices`).
- Паузы = длина реплики + ~0,8 с (замеряй реплики заранее: `node skills/new-video/engine/measure-tts.cjs`); между
  репликами тишина. Если у шага уже есть свой звук (озвучка слова, «проговаривание» в тесте),
  реплика диктора выносится в отдельный шаг-подводку перед ним.
- Слова, которые «произносит пользователь», озвучиваем голосом, отличным от голоса приложения
  (в роликах: озвучка — Samantha, проговаривание — Daniel).
- Текст реплик — лаконичный и грамотный, без канцелярита; объяснение цели экрана важнее
  пересказа кнопок.
- Длинный ролик спокойно живёт 3+ минуты: подробное объяснение важнее хронометража.
  Специфичные ролики — 15–40 с.
- Ролик должен быть **самодостаточным**: первый кадр — осмысленный экран, последний — результат действия.
- **Подписи не должны перекрывать sticky-кнопки**; если подпись всё же нужна — используй `hint`
  (он сам встаёт над элементом) или снимай без подписей: смысл читается по курсору.
- Не жми «назад» там, где приложение само меняет экран: после загрузки готовых курсов `loadCoursesFx` делает `goToRoot()` и возвращает на «Курсы» — стрелки «назад» на этом экране уже нет.

### Моки фич, которых нет в браузере

- Нативную часть Android можно показать мок-мостом (`initScripts`, пример — `scenarios/task.ru.cjs`):
  `window.AndroidBridge` рисует кнопку «Сканировать текст», отдаёт распознанный текст, отвечает
  на распознавание речи. В мок-мосте обязательны `hasRecognition`, `speak`, `asrStatus`
  с установленным артефактом (иначе вылезет шит «Распознавание не загружено»).
- Переводы (слова по удержанию, «Перевести всё») ходят в интернет — подменяй их `routes`
  на словарь, чтобы в кадр попал правильный перевод и ролик не зависел от сети.
- Проверку произношения задавай через `speech`/`speechDelay` (мок распознавания) — или через
  очередь слов в мок-мосте для автоматического режима теста.

## Частые ошибки

- **`Не нашёл элемент`** — проверь точный текст/aria-label в приложении; ищи по подписи кнопки, а не по её коду. Для полей — по метке («Название курса»).
- **Проверка произношения «прощает» ошибку.** `assessPronunciation` считает слово верным при совпадении первой буквы и близкого согласного скелета: «toast»/«Thursday» проходят для «Tuesday». Плюс короткие слова (≤4 букв после сжатия удвоений: `coffee` → `cofe`) принимают **любое** услышанное слово. Для демонстрации ошибки бери длинное слово (≥5 букв после сжатия) и заведомо непохожее («kitchen» / «banana»), либо назови слово по-русски.
- **Переворот карточки не срабатывает от мыши.** Обёртка карточки ставит pointer capture, и `click` переадресуется на неё — обработчик переворота не получает событие (кнопки озвучки/микрофона не страдают: у них `stopPropagation`). В сценарии переворачивай тачем: `{ tap: 'Monday', touch: true }`. Микрофон и озвучка есть только на лицевой стороне — проверку произношения делай до переворота.
- **Рамка вокруг круглой кнопки** (микрофон) смотрится плохо — для неё `hintRing: false`: тултип показывается, обводки нет.
- **Публикуем только mp4** — h264 играет во всех целевых браузерах; webm-фолбэк не используем, чтобы не хранить вторую копию ролика.
- **Обрезка низа видео на телефоне.** Кадр 390×844 не совпадает с пропорциями экрана; плеер обязан держать `object-fit: contain` и `max-height: calc(100vh - env(safe-area-inset-*))` — не заменяй на `height: 100%`.
- **Подписи поверх кнопок.** Смотри кадры перед публикацией (шаг 3).
- **`say` не найден/голос отсутствует** — реплика озвучится голосом по умолчанию; список голосов: `say -v '?'`.
- **`edge-tts`: «No audio was received»** — сервис иногда отвечает ошибкой; `audio.cjs` повторяет попытку 3 раза, при повторной неудаче просто запусти сборку ещё раз.
- **Забыт `--to`** — файлы останутся в `$TUT_OUT`, в приложении появится 404 на видео.

## Что не снимается браузером

Нативные фичи Android (скачивание офлайн-голосов и моделей распознавания, OCR-камера, виброотдача, нативные шиты) в браузере недоступны: такие ролики снимаются на устройстве/эмуляторе (adb/Maestro), либо в браузере показывается только веб-часть (меню, настройки, шит распознавания с моком).
