# Обучающее видео для «Базы знаний»

## Контекст (прочитать перед работой)

- Экран — `app/src/features/knowledge/ui/KnowledgeView` (экран навигации `knowledge`, пункт меню «База знаний»). Превью-карточка: постер, полупрозрачное затемнение, название в верхнем регистре; тап — полноэкранный плеер на `BottomSheet fullHeight` с крестиком.
- Список видео — `app/src/features/knowledge/videos.ts` (`KNOWLEDGE_VIDEOS`: `id`, `title`, `src` mp4, `webm`-фолбэк, `poster`).
- Файлы — `app/public/videos/<id>.mp4|.webm|.jpg` (пути строятся от `import.meta.env.BASE_URL`).
- Видео грузится **только по клику** (элемент `<video>` монтируется вместе с плеером), постеры — `loading="lazy"`. Список может расти без оглядки на вес видео.
- Движок записи — `skills/new-video/engine/`: `runner.cjs` (Playwright: настоящие тапы, свайпы, ввод, виртуальный курсор, сцены с печатающимся текстом и тултипы у элементов) и `audio.cjs` (сборка mp4 + webm + звук + постер).
- Сценарии — `skills/new-video/scenarios/<id>.cjs` (шаблон — `_template.cjs`). Сценарий снятого ролика хранится рядом: по нему ролик можно пересобрать.
- План роликов — `skills/new-video/SCENARIOS.md`.

### Зависимости движка

`playwright-core` и `ffmpeg-static` ищутся в `node_modules` репозитория, затем в `$TMPDIR/opencode/e2e`. Если их нет:

```bash
mkdir -p "$TMPDIR/opencode/e2e" && cd "$TMPDIR/opencode/e2e" && npm i playwright-core ffmpeg-static
```

Chromium берётся из кеша ms-playwright (`$TUT_CHROMIUM` — чтобы указать явно). `say` (macOS) нужен только для озвучки.

### Переменные окружения

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `TUT_OUT` | `$TMPDIR/opencode/tutorial-out` | каталог артефактов (webm, timeline.json, mp4, jpg) |
| `TUT_BASE` | `http://localhost:5173/` | адрес приложения |
| `TUT_CHROMIUM` | свежий из кеша ms-playwright | путь к Chromium |

## Ключи шага

Шаг — один объект; действие одно, остальное — оформление. Полный список — в шапке `engine/runner.cjs`.

| Ключ | Что делает |
| --- | --- |
| `scene` | карточка сцены `{ title: 'Сцена 1', text: 'Для начала загрузим курс.' }`: затемнение, номер сцены и текст, печатающийся по буквам (45 мс/буква, пауза 1500 мс) |
| `hint` | тултип у элемента действия: `{ hint: 'Выберите уровень владения языком', tap: 'Выберите уровень' }` — подсветка рамкой, пауза 1400 мс, действие, скрытие; работает с `tap`/`swipe`/`type`, без действия — висит по центру сверху |
| `tap` / `tapAt` | тап по кнопке/radio/тексту или по координатам |
| `type` | ввод: `{ target: 'Название курса', text: 'Привет', delay: 90 }` |
| `swipe` | свайп: `{ target: 'Monday', dir: 'left' }` |
| `back` | тап по стрелке «назад» |
| `wait` / `pause` | пауза до/после действия |
| `speech` / `speechError` / `speechDelay` | что «услышит» распознавание при тапе по микрофону |
| `say` / `sayLang` / `sayDelay` / `sayRate` / `voice` | реплика для звуковой дорожки (macOS `say`) |
| `eval` | произвольный код в контексте страницы |

## Шаги

1. **Сценарий.** Создай `skills/new-video/scenarios/<id>.cjs` по `_template.cjs`. `seed` — состояние стора на старте (курс/урок/задание/карточки/настройки), `steps` — действия. Список ключей шага — в шапке `engine/runner.cjs`.
2. **Запись.** Подними приложение и запусти движок из корня репозитория:

   ```bash
   npm run dev
   node skills/new-video/engine/runner.cjs skills/new-video/scenarios/<id>.cjs
   ```

   Результат: `$TUT_OUT/<name>.webm` + `<name>.timeline.json`. Движок печатает шаги и ошибки страницы; при падении пишет, какой элемент не нашёл и что сейчас на экране. Для отладки подсказок: `TUT_DEBUG_HINT=1` печатает координаты тултипа.

3. **Проверь кадры** (playwright-ffmpeg умеет только webm, поэтому смотри через ffmpeg-static):

   ```bash
   FF=$(node -e "console.log(require('$TMPDIR/opencode/e2e/node_modules/ffmpeg-static'))")
   $FF -y -ss 3 -i "$TUT_OUT/<name>.webm" -frames:v 1 /tmp/frame.png
   ```

4. **Сборка и публикация** (mp4 + webm-фолбэк + постер сразу в приложение):

   ```bash
   node skills/new-video/engine/audio.cjs <name> --trim=auto --webm --poster=0.6 --to=app/public/videos
   ```

   `--trim=auto` отрезает загрузку приложения до первого кадра (по `timeline.readyMs`), поэтому постер и начало ролика — ровно тот экран, с которого начинается сценарий. Если в сценарии есть реплики `say`, звук подмешивается в mp4 автоматически (`--offset=<мс>` — подстройка, `--voice-ru=` и т.п. — голоса).

5. **Регистрация** — строка в `KNOWLEDGE_VIDEOS` (`app/src/features/knowledge/videos.ts`): `id` = имя файла, `title` — как показывать на карточке (заглавные буквы делает CSS), `src`/`webm`/`poster` — через `asset('videos/<id>.<ext>')`.

6. **Проверка.** `npm run lint`, `npm run typecheck`, `npm run build`; в приложении — Настройки → База знаний: постер, клик, полноэкранный плеер, крестик. Быстрый смоук (если есть) — `node $TMPDIR/opencode/e2e/knowledge-check.cjs`. Файлы видео и правки — в git.

## Правила съёмки

- Формат — **портрет 390×844** (запись 780×1688), тёмная тема; так же выглядит и на телефоне.
- Обучающий ролик собирается из **сцен**: перед каждой сценой — карточка `scene` («Сцена N» + текст, печатающийся по буквам), внутри сцены — действия с `hint`-тултипами у элементов («Выберите уровень владения языком»). Без сцен и тултипов ролик читается хуже.
- Ролик должен быть **самодостаточным**: первый кадр — осмысленный экран, последний — результат действия (например, курс появился в списке, тест пройден). Специфичные ролики — 15–40 с, обзорный — до 2 минут.
- **Подписи не должны перекрывать sticky-кнопки** (например «Загрузить» на экране готовых курсов) и выбор уровня в bottom sheet. Если перекрытие неизбежно — используй `hint` (он сам встаёт над элементом) или снимай без подписей: смысл читается по курсору.
- **Тултип сразу после действия скрывается** — не нужно ждать `hintAfterMs`: пауза после тапа идёт уже без подсказки, чтобы та не висела поверх нового экрана.
- Озвучка (`say`, `sayLang`) — когда ролик смотрят со звуком; для коротких операций обычно достаточно немого ролика.
- Не жми «назад» там, где приложение само меняет экран: после загрузки готовых курсов `loadCoursesFx` делает `goToRoot()` и возвращает на «Курсы» — стрелки «назад» на этом экране уже нет.

## Частые ошибки

- **`Не нашёл элемент`** — проверь точный текст/aria-label в приложении; ищи по подписи кнопки, а не по её коду. Для полей — по метке («Название курса»).
- **Проверка произношения «прощает» ошибку.** `assessPronunciation` считает слово верным при совпадении первой буквы и близкого согласного скелета: «toast»/«Thursday» проходят для «Tuesday». Для демонстрации ошибки бери заведомо непохожее слово или другой язык (например, назвать слово по-русски — на экране будет «Ошибка! Услышано "вторник", нужно Tuesday»).
- **h264 не играет в Chromium без проприетарных кодеков** — поэтому публикуется пара mp4 + webm (`--webm`), а компонент подключает оба `<source>`.
- **Обрезка низа видео на телефоне.** Кадр 390×844 не совпадает с пропорциями экрана; плеер обязан держать `object-fit: contain` и `max-height: calc(100vh - env(safe-area-inset-*))` — не заменяй на `height: 100%`.
- **Подписи поверх кнопок.** Смотри кадры перед публикацией (шаг 3).
- **`say` не найден/голос отсутствует** — реплика озвучится голосом по умолчанию; список голосов: `say -v '?'`.
- **Забыт `--to`** — файлы останутся в `$TUT_OUT`, в приложении появится 404 на видео.

## Что не снимается браузером

Нативные фичи Android (скачивание офлайн-голосов и моделей распознавания, OCR-камера, виброотдача, нативные шиты) в браузере недоступны: такие ролики снимаются на устройстве/эмуляторе (adb/Maestro), либо в браузере показывается только веб-часть (меню, настройки, шит распознавания с моком).
